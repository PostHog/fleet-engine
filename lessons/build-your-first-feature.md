## One sentence starts a build

Your hub and node are running. Your first thread is open. You type just one sentence. Build a dark mode switch for the settings page. What comes back is a pull request. It's tested, reviewed by a second model, and proven. Plus the few decisions only you can make. You can also skip the word build. Just describe the change. The Everyday preset turns on the Orchestration pack. With it, every change starts the same way.

## Hedge sizes the work first

Before any code, the build skill sizes the work. A question just gets an answer. A one-off is one pull request. Up to about four hundred lines. It starts without a plan question. An issue is a stack of pull requests. Up to three of them. You read its plan once, before the code. Anything bigger becomes a map. It gets a conductor and its lanes. The thread says its verdict in one line. So you know right away how big it is.

## Worth it? Then it starts

Next, the impact check asks one thing. Does the work pay into a goal? The first time, it asks for your goal. Work that pays into it starts now. Work that does not, parks. A park keeps its reason. And the event that brings it back. Such as a date. Or a second report of the same problem. So nothing is lost. And nothing starts just because it was asked for.

## Open questions come first

Some work has a question the code cannot answer. Maybe a fact outside the repository decides the shape. Such as a price, or a limit. Then a research worker reads it first. Is the look still open? Then a prototype comes first. You see it before anyone builds it. Does the change move a boundary between modules? Then an architecture step draws it first. A prototype or an architecture step makes it an issue. So you approve the plan before the code.

## Tests first, then the code

Then the work starts on a node. It gets its own copy of the repository. Does the change alter behaviour? Then the agent first writes a test that fails. The dark mode switch does not exist yet. Then it writes the code that makes the test pass. So the proof is part of the change. From the very start. And the next change cannot quietly break it.

## A second model reviews it

The agent opens a draft pull request. Then a reviewer reads it. Are Claude and ChatGPT both signed in? That is the default plan. Then a GPT model reviews the code Claude wrote. The reviewer does not share the writer's blind spots. A risky change gets the QA swarm. So does any change you want to ship. That is several reviewers, each with its own lens. The more risk, the more reviewers. Each valid finding is fixed with a test. The loop stops when a review finds no new bug.

## Read the risk, then the proof

The pull request comes back. You read three parts. The risk callout sits at the top. It says how far a mistake could reach. Whether a revert undoes it. And how to switch it off. The testing section says what was run. And what it showed. A change you can see gets screenshots. Is something left? Then known issues says what, and why. In a minute, you know whether it's safe to ship.

## You decide what is yours

Along the way, small calls come up. One more review round, maybe. Or a proof that could not run. By default, the thread asks you each time. It sends a card you answer in the inbox. Once you trust it, there's one setting. `hedge set pull-requests.autonomy=end`. Then it decides those calls alone. And it shows you one table at the end. Some things still come to you at once. A one-way door. A security finding. A blocked action.

## Two phrases decide how far it goes

By default, it stops at a draft pull request. You mark it ready for review yourself. Say full send, and the QA swarm runs. The pull request is marked ready. Once a teammate approves, it merges. Then it watches the rollout. Stamp it uses your team's approval bot instead. When your team has one. The next lesson, Ship it, shows each word.

## Go deeper when you need it

That is a whole build. From one sentence to a proven pull request. You typed one line. You answered what was yours. And you read one page. The library picks up where this one pointed. The QA swarm. Grilling and prototypes. The map. And impact.
